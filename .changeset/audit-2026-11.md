The 2026-11 audit: three parallel passes over the BFF server, `lukk-core` and the Nuxt runtime, plus a contract check against lukk's `fix/audit-2026-11`. No Blocker; every finding is fixed and pinned by a test.

**lukk-core**

- **Credentials could reach a foreign origin with an empty or `/` `baseURL`.** `request('\t/evil.com/x')` was judged same-origin on its canonical form and then joined from the raw string, which the URL parser turns into `//evil.com/x` — with the bearer and the confirmation token attached. The join now uses the string the guard judged. lukk-nuxt never passes a caller's path with such a base; a raw consumer could.
- **`onTokens` and `onUnauthenticated` fire once per refresh**, not once per request that was waiting on it.
- **A 401 that lands after the token was already renewed retries with it** instead of spending a second rotation; it is still refused with `SESSION_CHANGED` if the new token is another account's, and still renews if that token is refused too.
- `Content-Type: application/json` is defaulted for a string body only, so a `FormData` or `URLSearchParams` body keeps its own type and boundary.
- `restore()` answers `null` for a 2xx that is not a token pair, as its type says.
- `shapeUser` no longer unwraps a user that has an `id` and a `data` attribute of its own.
- `LukkError.message` is always a non-empty string, and `errors` is only ever an object or array (never a string or number); `retryAfter` reads at most nine digits.

**lukk-nuxt**

- **BFF: a response slower than ten minutes could write an ended session's cookie back** — over the new session's after a sign-in (a false logout at the next refresh), or over the one a logout cleared. A session that ends while a response is out for it — here, or on another instance through `session.sharedStore` — now leaves a tombstone that withholds that cookie however late it arrives.
- **BFF: lukk's `Retry-After` is relayed** on a `429` or a timed `423`, so `LukkError.retryAfter` is set in BFF mode as it already was in direct mode.
- **Another tab changed the session and the user could not be reloaded:** the tab no longer keeps showing the previous account while acting as the new one. It shows `restoreFailed` (retry with `initSession()`); nothing that holds the session is cleared.
- **A step-up that answers after a logout, a sign-in, another tab's account change or a renewal that came back as another account is not recorded** — password and passkey alike.
- **`useLukkFetch` sent the bearer to the app's origin for a path ofetch does not join.** ufo reads more as a scheme than the URL grammar does (`user_profiles:batchGet`, `.well-known:x`), leaves such a path unjoined, and the browser resolves it against the page; it is now treated as what it is, a path on the page's origin, and gets credentials only if that is the API's. Never an attacker's origin.
- A refresh that was waiting on a failed sign-in no longer goes out beside the sign-in queued behind it.
- BFF: a 2xx from `/refresh` that is not a token pair is treated as an outage rather than sealed; a `GET` to `/api/_lukk/logout` is a `405`, not a logged `502`; a replacing sign-in revokes the pair the old session holds when lukk answers, not the one read before the call; `Vary` gains `Cookie` instead of being overwritten; the app-API proxy's `502` is `private, no-store`; a `Connection` option that is not a header name no longer answers `500`.
- The module refuses a `mode` that is neither `'bff'` nor `'direct'`, judges a session secret set through `runtimeConfig.lukk.sessionPassword` (the environment variable still wins, as at runtime), and warns when a production build talks to lukk or the app API over plain `http://` on another host.
